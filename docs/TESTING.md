# Перевірка на справжньому комп'ютері (Artix + NVIDIA 580xx)

Покроковий план перевірки OBS-Legacy на власному залізі. Кожен запуск пише повний звіт у
`~/.cache/obs-studio-nvenc-artix/reports/`; що надсилати, якщо щось не так, — наприкінці.

**Уже перевірено** на Artix з dinit, GeForce GTX 1060 3GB, драйвері 580.196.07 і Intel Xeon E3-1275 V2
(OBS 33.0.0 і 33.0.1): «Перевірити систему»; збирання під залізо й встановлення пакетами pacman із заміною
`obs-studio-git`, `ffmpeg` і AUR-версії obs-multi-rtmp; «Оновити» (новий OBS, новий реліз плагіна,
«Оновлень немає») і «Перезібрати»; запис через NVENC у самому OBS (1080p60, без пропущених кадрів),
Browser Source і плагіни — зокрема з AUR — поверх пакета; `h264_nvenc` і `hevc_nvenc` у
`ffmpeg-legacy-580xx`; pacman-хук; сповіщення через службу dinit (userspawn). Усі 18 плагінів каталогу
збираються з OBS 33.0.1, і кожен їхній модуль знаходить усі символи OBS (`ldd -r`); у самому OBS
випробувано obs-multi-rtmp, pipewire-audio-capture, composite-blur і waveform.

Дії `install`, `update`, `rebuild`, `rollback`, `uninstall` і `deps` питають пароль sudo/doas і
підтвердження `[y/N]`, тож запускай їх у програмі `obs-legacy`. `check`, `status`, `plugins`, `clean` і
`package` можна запускати й просто скриптом: `bash ~/.local/share/obs-legacy/build-obs-nvenc-legacy-artix.sh
check`.

## 0. Зібрати відомості про систему

```bash
cat /proc/driver/nvidia/version; nvidia-smi --query-gpu=name,driver_version,compute_cap --format=csv,noheader
```

```bash
pacman -Q | grep -Ei 'nvidia|obs-studio|ffmpeg|qt6-base|mbedtls|rust'
```

```bash
cat /etc/os-release | head -3; cat /proc/1/comm; echo "DE=$XDG_CURRENT_DESKTOP TERMINAL=$TERMINAL"
```

Що записати: модель відеокарти, точну версію драйвера (очікується 580.xx), init, DE і термінал, чи стоїть
системний `obs-studio`, версії ffmpeg (OBS 33 потребує ≥ 8.0) і qt6-base.

## 1. Встановлення програми

```bash
git clone https://github.com/YellowHearth1/OBS-Legacy.git && cd OBS-Legacy
```

```bash
./install.sh
```

Якщо OBS-Legacy уже встановлено з цієї теки, оновлення — `git pull && ./install.sh --update` (або пункт
«Додатково → Оновити OBS-Legacy»).

Очікується: банер із попередженням про Claude Code і подякою sl5net; якщо Rust немає — пропозиція
`pacman -S --needed rust`; `cargo build --release --locked`; `[OK]` для програми, ярлика в меню й іконки;
питання про ярлик на робочому столі й про сповіщення; наприкінці «ГОТОВО ✓».

- [ ] Ярлик «OBS-Legacy» з'явився в меню програм з іконкою (відеокарта й напис «580xx»).
- [ ] Клацання відкриває **вікно термінала** з першим екраном (логотип, жовта рамка «Скрипт зроблений за
      допомогою Claude Code», подяка sl5net). Якщо вікно не відкрилося — записати, який термінал
      стоїть, і перевірити `TERMINAL`/`xdg-terminal-exec`.
- [ ] Ярлик на робочому столі запускається (у GNOME/Xfce може знадобитися «Дозволити запуск»).
- [ ] `obs-legacy --version` у терміналі (якщо `~/.local/bin` є в PATH).

### 1а. Готовий пакет замість `install.sh`

Спершу `./install.sh --uninstall`, якщо програма вже стоїть з вихідних кодів. Пакет — з релізу на GitHub:

```bash
sudo pacman -U obs-legacy-0.0.2-1-x86_64.pkg.tar.zst
```

- [ ] `pacman -Qi obs-legacy` — версія релізу; `command -v obs-legacy` → `/usr/bin/obs-legacy`.
- [ ] Ярлик «OBS-Legacy» з іконкою є в меню й відкриває вікно термінала з першим екраном.
- [ ] У «Додатково» немає «Оновити OBS-Legacy» (теки з вихідними кодами немає) — так і має бути.
- [ ] Коли вийде новіший реліз, сповіщення радить пакет із нього й `sudo pacman -U …`, а не `git pull`.
- [ ] `./install.sh` поруч із пакетом попереджає, що копія в `~/.local/bin` його перекриє.
- [ ] `sudo pacman -R obs-legacy` прибирає програму; пакети `*-legacy-580xx` лишаються.

## 2. Головний екран

- [ ] «Твоя система» (клавіша `d`): відеокарта, «Драйвер … ✓ гілка 580xx (legacy)», «NVENC API 13.0 ✓».
      Якщо NVENC «невідомо» — перевірити, що є `libnvidia-encode.so.1` (`ldconfig -p | grep nvidia-encode`).
- [ ] «Оновлення: найновіший стабільний OBS: …» (потрібна мережа).
- [ ] Значки меню (◎ ▼ ▶ ⊕ ⋯ ≡ ◫ ↩ ◈ ↪ ⌫ ✗ ? ×, ◆ біля рекомендованого пункту) і спінер (⠋)
      відображаються, а не квадратиками. Якщо ні — записати шрифт і термінал.
- [ ] Кольори нормальні (truecolor/256). Миша: клацання вибирає, повторне — запускає, коліщатко гортає.
- [ ] Прозорий термінал (Kitty з `background_opacity`): інтерфейс на суцільному темному фоні, текст
      читається. «Налаштування → Суцільний фон» вимикає фон одразу, без перезапуску.
- [ ] Панель «Що далі»: на першому запуску — «Почни з перевірки системи», курсор стоїть на
      «Перевірити систему» (◆). Після перевірки — «Систему перевірено — можна встановлювати».
- [ ] Вікно 80×24 і менше: усе читається або є підказка «Збільш вікно».
- [ ] Мова: «Додатково → Налаштування → Мова інтерфейсу» → `en` — меню, «Що далі», довідка й діалоги одразу
      англійською, а наступне завдання (напр. «Перевірити систему») друкує `[WARNING]`, `[HINT]`, `Report:` і
      звіт теж англійською; `uk` — назад українською; `auto` — за локаллю системи (`uk_*` — українська, інше —
      англійська). Без програми: `UI_LANG=en bash ~/.local/share/obs-legacy/build-obs-nvenc-legacy-artix.sh
      help`. Старі українські звіти в «Звітах» показують правильний результат і в англійському інтерфейсі.

## 3. «Перевірити систему» (`check`)

Займає 5–15 хв: завантаження вихідних кодів OBS із сабмодулями, CEF (~300 МБ) і плагінів. Нічого не змінює.

- [ ] Етапи йдуть списком ліворуч, вивід — праворуч, видно прогрес завантаження CEF.
- [ ] Етап «Оптимізація під залізо»: дистрибутив, процесор (напр. `ivybridge`, x86-64-v2, AVX), відеокарта
      (напр. Pascal, CUDA 6.1), драйвер і його пакет, прапорці `-march=native -mtune=native -O2 …`.
- [ ] «nv-codec-headers»: «Драйвер знає NVENC API 13.0 → найновіші сумісні заголовки: n13.0.19.1».
- [ ] «SHA-256 збігається з офіційним хешем OBS» для CEF.
- [ ] У розділі «Плагіни» для кожного вибраного плагіна написано «буде зібрано <версія>».
- [ ] Пробна конфігурація CMake пройшла: «ПЕРЕВІРКУ ПРОЙДЕНО», Browser Source, NVENC, mbedtls3. Якщо бракує
      пакетів для збирання, пробну конфігурацію пропущено з порадою — це нормально (див. нижче).
- [ ] Картка «✓ Перевірити систему — готово» з «Зверни увагу / Що далі».
- [ ] `o` відкриває звіт у програмі, `c` копіює шлях (перевірити `wl-paste`), `e` відкриває файл у
      текстовому редакторі.
- [ ] Без пакетів для збирання: на картці головна кнопка «Виправити: встановити пакети» → діалог → `deps`
      (y, пароль) → «Перевірити систему ще раз» → усі етапи ✓; у «Твоїй системі» «Пакети ✓ усі на місці».
      Для ffmpeg знадобляться ще `amf-headers spirv-headers` — їх ставить та сама кнопка.

## 4. «Встановити / оновити OBS» (`install`)

Займає 30–90 хв (уперше з ffmpeg — довше). Під час роботи треба відповісти на запитання (`y`) і ввести
пароль sudo/doas просто у вікні програми.

- [ ] Запит на встановлення пакетів для збирання (якщо чогось бракує), банер «введи y або n».
- [ ] Компіляція з прогресом `N/M` і оцінкою часу.
- [ ] `obs-nvenc-test`: `nvenc_supported=true`, «NVENC працює з цією збіркою». **Головна перевірка всього
      проєкту.**
- [ ] «Налагоджувальну інформацію прибрано … (CEF): ~2100 МБ → ~550 МБ».
- [ ] «Плагін obs-multi-rtmp зібрано» (і так само інші вибрані). Плагіни збираються з тим самим профілем (у
      `plugins/<id>/build.log` видно `-march=native`). Якщо плагін не зібрався, це не блокує OBS: зберегти
      `~/.cache/obs-studio-nvenc-artix/plugins/<id>/build.log`.
- [ ] «Усі бібліотеки знаходяться» (ldd).
- [ ] ffmpeg: рядки «ffmpeg збирається N хв…», потім «ffmpeg зібрано, NVENC працює (h264_nvenc, hevc_nvenc)».
- [ ] «Пакети pacman»: `obs-studio-legacy-580xx-<версія>-<N>-x86_64.pkg.tar.zst` (~170 МБ) і пакет для
      кожного плагіна.
- [ ] «Встановлення пакетів (pacman -U)»: план замін (`obs-studio` / `obs-studio-git`, AUR-версії плагінів,
      `ffmpeg`), запитання скрипта, потім запитання pacman «… конфліктують. Видалити …? [y/N]» — `y`.
- [ ] Якщо раніше стояла стара версія OBS-Legacy (збірка в `/opt`): «Прибираю стару схему встановлення» —
      зникли `/opt/obs-studio-nvenc`, `/usr/local/bin/obs`, `/etc/pacman.d/hooks/90-obs-legacy.hook`.
- [ ] «ГОТОВО: OBS … зібрано під цей комп'ютер, NVENC перевірено, пакети встановлено.»
- [ ] Після цього:

  ```bash
  pacman -Qs legacy-580xx
  ```

  ```bash
  command -v obs
  ```

  Очікується: пакети OBS, плагінів і ffmpeg; `obs` → `/usr/bin/obs`. У «Твоїй системі» — «Команда obs ✓
  /usr/bin/obs → OBS-Legacy».
- [ ] `ffmpeg -hide_banner -f lavfi -i testsrc2 -frames:v 30 -c:v h264_nvenc -f null -` — без помилки
      «Driver does not support the required nvenc API version».
- [ ] Будь-який AUR-плагін, що потребує `obs-studio`, ставиться без конфліктів (напр. через yay/paru).
- [ ] Будь-яке `sudo pacman -S <щось>`: наприкінці рядок хука «OBS-Legacy: перевірка бібліотек OBS і
      плагінів...» без попереджень.

## 5. Перевірка самого OBS

- [ ] OBS запускається з меню, командою `obs` і пунктом «Запустити OBS» у програмі.
- [ ] Довідка → Про програму: очікувана версія (напр. 33.0.1).
- [ ] Налаштування → Вивід → Розширений: кодувальник **NVIDIA NVENC H.264** (і HEVC, якщо відеокарта вміє).
      AV1 на Pascal і Maxwell немає — це нормально.
- [ ] Тестовий запис 10–20 с через NVENC без помилок; `nvidia-smi dmon -s u` під час запису показує
      навантаження в стовпчику `enc`.
- [ ] Джерело «Браузер» (напр. `https://obsproject.com`) показує сторінку, «Доки → Власні браузерні доки»
      працюють. Апаратне прискорення браузера OBS сам вимикає на пропрієтарному драйвері NVIDIA — так
      задумано в OBS.
- [ ] obs-multi-rtmp: у меню «Доки» є його док («Multiple output»).
- [ ] Інші вибрані плагіни видно у відповідних меню. OBS 33: «Інструменти → Менеджер плагінів».
- [ ] Журнал OBS (`~/.config/obs-studio/logs/`, останній файл): `[obs-nvenc] NVENC version: 13.0`, рядки
      `obs-browser`, немає помилок завантаження модулів. Рядки «Failed to load 'en-US' text for module:
      'decklink-…'» — так у самого OBS (без плати Blackmagic), «Failed to load 'uk-UA' text» — у плагіна
      немає українського перекладу.

## 6. Довгострокові функції

- [ ] pacman-хук. Перевстановлення будь-якого маленького пакета теж запускає хук:

  ```bash
  sudo pacman -S sed
  ```

  Очікується рядок «OBS-Legacy: перевірка бібліотек OBS і плагінів...» без попереджень.
- [ ] «Додатково → Стан і оновлення» показує набори пакетів, плагіни, хук і оновлення OBS та плагінів.
- [ ] «Плагіни»: зняти чи поставити галочку → «Збережено». У `~/.config/obs-legacy/settings.env` змінюється
      рядок `OBS_PLUGINS=`.
- [ ] «Налаштування»: змінити, напр., «Скільки наборів тримати» й перевірити файл. Неправильне значення
      (0, букви) дає помилку, а не зберігається.
- [ ] «Відкат на іншу збірку» після другого встановлення: ставить попередній набір пакетів (pacman
      попереджає про старіші версії), назад — теж.
- [ ] Ctrl+C під час `check`: перший раз — попередження, другий — переривання, картка «перервано».
- [ ] Відповідь «n» на запитання про пакети: картка «скасовано» (жовта), а не «помилка»; у звіті
      `Результат: скасовано`.
- [ ] «Додатково → Звіти»: список із результатом кожного запуску; у переглядачі `n`/`p` стрибають між
      попередженнями й помилками.
- [ ] «Додатково → Оновити OBS-Legacy», коли в репозиторії з'являться нові коміти.
- [ ] «Додатково → Сповіщення про оновлення» → «Увімкнути»: картка ✓, пробне сповіщення на робочому
      столі. Стан:

  ```bash
  obs-legacy --notifier status
  ```

  Очікується служба своєї init-системи (на Artix з dinit — `служба dinit`), «Опис служби dinit перевірено»
  і «Фонова перевірка працює».
- [ ] Після перезавантаження (чи виходу й входу) фонова перевірка знову працює (`--notifier status`), а
      в `~/.local/state/obs-legacy/updates.log` з'являються рядки «Перевірка: …».
- [ ] Коли вийде новий OBS чи реліз плагіна, приходить одне сповіщення; кнопка «Відкрити OBS-Legacy»
      відкриває програму, а «Що далі» каже те саме. Повторних сповіщень про ту саму версію немає.
- [ ] «Вимкнути» в тому самому пункті прибирає службу (`--notifier status` → «Вимкнено»).

## 6а. Оновлення й перезбирання

- [ ] OBS-Legacy уже встановлено, нового немає: «Встановити / оновити OBS» відкриває «Оновити OBS?», Enter →
      за кілька секунд «ОНОВЛЕНЬ НЕМАЄ», у картці — «Підсумок: оновлень немає — встановлено найновіше…»,
      `pacman -Q obs-studio-legacy-580xx` не змінився.
- [ ] Вийшов новий OBS (чи реліз плагіна): «Оновити» збирає й ставить; у картці — «Підсумок: OBS A → B».
- [ ] R («Перезібрати») у тому самому діалозі: «Чиста конфігурація CMake», повне збирання, у картці —
      «OBS … перезібрано начисто».
- [ ] Обрив: під час збирання закрий вікно OBS-Legacy (чи Ctrl+C ×4), відкрий знову — «Що далі» каже «Минуле
      збирання обірвалося», Enter → діалог «Перезібрати OBS начисто?».
- [ ] Скасування на останньому запитанні («Встановити пакети OBS-Legacy?» → `n`): «Що далі» — «Пакети
      зібрано, але не встановлено»; Enter → «Оновити» → «Готовий набір, ще не встановлений» → без збирання
      одразу запитання → `y` → «Підсумок: поставлено готовий набір …».
- [ ] На будь-якому `[y/N]`: «н» чи «т» → підказка про українську розкладку й те саме запитання ще раз;
      стрілки під час збирання гортають вивід і на відповідь не впливають.

## 7. Видалення (наприкінці, за бажанням)

- [ ] «Видалити OBS-Legacy»: `pacman -S ffmpeg` (pacman питає, чи замінити `ffmpeg-legacy-580xx`) і
      `pacman -R` пакетів `*-legacy-580xx`; потім `sudo pacman -S obs-studio` повертає OBS з репозиторію.
- [ ] `./install.sh --uninstall` прибирає саму програму.

## Що надсилати, якщо щось не так

1. Файл звіту з `~/.cache/obs-studio-nvenc-artix/reports/` (останній) — у програмі `c` копіює його шлях.
2. Для плагіна — `~/.cache/obs-studio-nvenc-artix/plugins/<id>/build.log`.
3. `obs-legacy --version`, `pacman -Q obs-studio-legacy-580xx ffmpeg qt6-base mbedtls3`, версію драйвера.
4. Знімок екрана програми, якщо проблема в інтерфейсі.

## Відомі ризики, на які варто звернути увагу

- Усі 18 плагінів збираються з OBS 33.0.1, але в самому OBS випробувано лише obs-multi-rtmp,
  pipewire-audio-capture, composite-blur і waveform. Для решти дивитися журнал OBS: чи завантажився модуль,
  чи немає двох копій.
- Новий OBS, реліз плагіна чи компілятор можуть зламати збирання плагіна (на OBS 33.0.1 так сталося з
  чотирма: застарілий API, `const` у C23, `Qt::GuiPrivate`; тепер це обходиться саме). OBS тоді ставиться
  без такого плагіна, а журнал — у `plugins/<id>/build.log`.
- Самооновлення («Оновити OBS-Legacy») і запуск у терміналі клацанням по ярлику на різних DE перевірено
  мало.
- Сповіщення в systemd, OpenRC, runit і s6 складено за документацією; на залізі перевірено лише dinit.
